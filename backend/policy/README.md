# Synthetic onboarding policy v1.1

This repository contains the 12 **synthetic** policies created for the capstone. `source/01_...txt` through `source/12_...txt` are text extracted from the corresponding PDF editions. The assistant retrieves short passages from those texts when OpenRouter is configured. The generated `requirements.json` is the deterministic portal catalogue, transcribed from the Supplier Category Guide, the eight category policies, and Evidence and Validation Standards. It defines exactly eight categories, 24 primary subcategories and 22 reusable requirement IDs.

The supplier selects one primary subcategory. Every code inherits `BASE-001`, `BASE-002`, `BASE-003` and exactly the additional IDs mapped to that code. Country is India in this synthetic version; there are no spend bands, multiple active categories, or hidden conditionals. Each checklist item shows what evidence is accepted, its required fields, and the two numbered checks. The server rejects an unknown category/subcategory and freezes the selected checklist at submission.

The upload gate checks that each requested document contains extractable text. One PDF or UTF-8 text file represents each requirement; where a policy requests more than one item, combine them into one PDF. The source policy also accepts PNG/JPG, but this app currently cannot extract text from images or image-only PDFs. **Uploading does not validate fields or thresholds.** Compliance records `ID.REVIEW` for each ready policy item and blocks automated approval until the specified checks can be implemented and independently tested. This preserves the distinction between a submitted packet and READY_FOR_APPROVAL.

These policies are invented demo rules, not actual procurement policy, registry verification or statutory guidance. If the source PDFs change, update both the texts and `requirements.json`, bump the version, and compare all 24 matrices and 22 check pairs before release. Previously submitted snapshots remain unchanged.
